# AGENTS.md

## Purpose

Local Python CLI that turns a rough project idea into a kickoff packet
(`PROJECT.md`, `TASKS.md`, `KICKOFF.md`) via a guided terminal interview.

## Stack

- Python 3.11+ (CI matrix: 3.11–3.14), setuptools, `src/` layout.
- Zero runtime third-party dependencies. Tests use stdlib `unittest` only.
  Do not add a dependency without a strong reason.

## Build / Run / Test

Run from a checkout without installing:

```bash
PYTHONPATH=src python3 -m kickstart init
```

Validation (same as CI — run both from repo root):

```bash
python3 -m compileall -q src tests
PYTHONPATH=src python3 -m unittest discover -s tests
```

Editable install / console-script smoke test:

```bash
python3 -m pip install -e .   # exposes `kickstart` entry point (kickstart.cli:main)
```

## Layout

- `src/kickstart/cli.py` — interview flow, prompts, read-only git repo inspection, write/overwrite handling.
- `src/kickstart/brief.py` — generated-file models and renderers.
- `src/kickstart/ui.py` — terminal rendering / menu helpers.
- `tests/` — `test_cli.py`, `test_brief.py`, `test_ui.py`.
- `docs/examples/` — committed sample output packets (new-project, existing-repo, repo-cleanup).

## Gotchas

- Strictly offline and side-effect-light: no network calls, no telemetry, never executes generated files. Keep it that way.
- Write mode only ever writes `PROJECT.md`, `TASKS.md`, `KICKOFF.md`, and refuses to overwrite existing files unless `--force`.
- Existing-repo inspection must stay read-only and shell-free: `subprocess.run()` without `shell=True`.
- `docs/examples/` output is regenerated by the renderers — keep it in sync when changing `brief.py`.
- Before changing repo visibility or releasing, scan the tree and reachable git history for local paths/secrets.
